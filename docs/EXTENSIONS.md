# 浏览器连接器

## 构建和安装

```powershell
Set-Location 'D:\gpt项目\自建域名邮箱'
npm run extension:build
```

Chrome/Edge 扩展管理页启用开发者模式，加载 `dist/extensions/full` 或 `dist/extensions/compat` 目录。不要同时启用两个版本操作同一账号。

1. 登录新平台，在“浏览器连接器”生成五分钟一次性配对码。
2. 打开扩展，填写本平台 HTTPS origin（本机允许 localhost/127.0.0.1 HTTP），主动授予平台访问权限，输入配对码并确认连接。
3. 选择平台账号；官网当前登录邮箱必须与目标邮箱一致。
4. 手动采集先验证官网身份，再读 Cookie，采集后再验证一次身份。
5. 开启登录后回填时，扩展监听 cookie/navigation；暂停会移除监听，已在途自动采集结果不再回填。
6. 平台可撤销扩展连接。扩展令牌 30 天过期；修改密码/禁用用户也撤销令牌。

完整版支持无痕代理和认证/Session 采集。兼容版使用相同采集核心，但不申请 proxy/webRequest 代理权限。

## 代理约束

- 在浏览器扩展详情中允许无痕访问。
- 作用域是整个浏览器无痕环境，不是每标签独立代理。
- 开启、切换、关闭前，必须先关闭所有已有无痕窗口。
- 切换时先设阻断 PAC，再取配置、验证代理出口；出口不符或请求失败时保留阻断，不返回 DIRECT。
- 浏览器重启清空临时认证信息后，扩展检测到残留代理状态会设为阻断，需重新启用。
- HTTP/HTTPS 代理支持认证。Chrome 的 SOCKS5 认证限制与服务端 curl 支持不同；浏览器连接器拒绝带账号密码的 SOCKS5。
- 断开平台连接不会偷偷清除已启用的代理；先关闭无痕窗口，再显式关闭代理。
- 扩展被禁用/卸载、被其他扩展或系统策略接管时无法控制浏览器的最终出口，不承诺此时仍能维持阻断。不要在此状态继续账号操作。

完整版为代理认证监听申请较广的 host 权限；只有扩展弹窗能发起平台命令，没有公开给任意网页的消息桥。Session 不写入扩展持久磁盘存储；连接 token 存在扩展 local，代理临时认证信息在 storage.session。

## 必须在用户真实浏览器验收

自动化只验证 API 配对/范围和离线 PAC 策略，不是下列行为的替代：

- 实际加载两个版本、主动确认新平台，绝不访问旧平台。
- 当前账号错误时，在读取/回填 Session 前阻止。
- 手动采集与登录后自动采集，采集后平台显示新的会话版本与历史。
- 暂停后不再监听/回填；旧配对码不能重用；撤销后拒绝回填。
- 存在无痕窗口时阻止切换；正确代理通过出口检测，错误密码/不可达/错 IP 均阻断。
- 浏览器重启后的状态、其他代理扩展冲突、主动关闭与平台断开。

未提供已登录官网的用户浏览器与可用代理，以上实际行为目前未标为通过。
